# 마루 서비스 기획서

외국인 방문객을 위한 한국 공예와 디자인 탐색 서비스

## 서비스 개요

마루는 외국인 방문객이 관심사와 체류 시간, 이동 부담을 입력하면 한국의 공예·디자인 공간을 연결한 코스를 확인하고, 장소 설명과 길찾기, 여행 기록까지 이어갈 수 있는 모바일 웹 서비스다. 첫 적용 범위는 서울이며, 기존 저장소의 공예·디자인 탐색 기능을 출발점으로 삼는다.

핵심 목표는 장소를 검색한 뒤 방문 순서를 다시 계획해야 하는 부담을 줄이는 것이다. 사용자는 박물관·갤러리·상업 공간이 어떤 경험으로 연결되는지 살펴보고 자신에게 맞는 코스를 저장한다. 공예 체험이나 상품 구매는 현장 또는 운영기관의 서비스를 이용하며, 마루가 예약·결제를 대행하는 것으로 표현하지 않는다.

## 해결하려는 문제와 이용자

서비스가 검증하려는 가설은 외국인 개별 여행객이 한국 공예와 디자인에 관심이 있어도 장소의 맥락, 이동 순서, 체험 가능 여부를 여러 곳에서 확인해야 한다는 점이다. 한국어 중심의 안내와 서로 다른 운영기관의 정보가 여행 계획의 부담이 될 수 있다. 이 가설의 규모나 심각도를 입증할 사용자 조사 결과는 아직 확보하지 않았다.

초기 이용자는 서울에서 반나절 이내의 문화 일정을 계획하는 외국인 개별 여행객이다. 공예·디자인을 처음 접하는 방문객, 실내 관람을 선호하는 방문객, 로컬 브랜드를 살펴보고 싶은 방문객을 구분해 사용성을 확인한다. 국적을 언어 설정만으로 확정하지 않고, 필요한 경우 본인이 선택한 여행 목적을 추천에 사용한다.

## 핵심 이용 흐름

사용자는 언어를 선택한 뒤 지역과 시간, 관심사, 동행 정보, 이동 부담 등 조건을 입력한다. 추천 목록에서 코스의 방문 장소와 순서, 예상 소요 시간 및 선택 이유를 비교한다. 코스 상세에서는 쉬운 해설과 방문 전 확인 사항을 읽고 외부 지도 길찾기로 이동한다. 선택한 코스는 여행 기록에 저장해 다시 연다.

시연의 중심은 조건 입력부터 코스 선택과 저장까지의 한 번의 완결된 흐름이다. 날씨 안내, 대화형 가이드, 사진 카드 등 보조 기능은 핵심 흐름을 이해한 뒤 소개한다. 저장은 기본적으로 해당 브라우저를 기준으로 하며, 다른 기기에서 동일하게 조회되는 계정 서비스는 서버 구성과 별도 검증이 필요하다.

## 차별화 방향

마루는 공예 작품을 감상하는 장소, 제작 과정을 이해하는 공간, 디자인 상품을 접하는 공간을 하나의 일정 안에서 설명한다. 장소의 수보다 코스가 연결되는 이유를 이해할 수 있는지가 중요하다. 코스 설명과 추천 조건이 실제로 일치하는지 검토하고, 운영시간이나 체험 예약처럼 변동이 큰 정보는 공식 안내로 연결한다.

또한 통신이 불안정한 이동 환경을 고려해 공개 화면과 기본 데이터를 기기에 저장한다. 이미 저장된 코스 상세 화면은 주소에 코스 식별자가 포함되어도 오프라인에서 열 수 있도록 처리한다. 외부 지도, 실시간 정보, 서버 기능은 인터넷 연결이 필요하다.

## 데이터와 구현 범위

현재 저장소에는 추천 코스 6개, 기본 장소 레코드 12개, 행사 레코드 6개, 국가유산 레코드 5개 및 데이터 출처 설명 5개가 있다. 이는 파일 내 레코드 수이며 이용자 수, 제휴기관 수, 검증 완료 데이터 수를 의미하지 않는다. 추천 코스 안의 장소는 화면 구성 과정에서 기본 장소와 병합될 수 있다.

공개 웹은 HTML·CSS·JavaScript와 정적 JSON으로 동작한다. 로컬 Python 서버는 같은 카탈로그를 조회하고 SQLite에 코스 저장 및 반응 기록을 보관한다. 별도의 Spring Boot 서버 코드도 있으나 이번 검증 대상은 정적 웹과 Python API다. 서로 다른 서버 구성을 동시에 완성된 운영 서비스로 소개하지 않는다.

대화형 가이드의 기본 제공 방식은 규칙과 저장된 콘텐츠를 사용하는 안내다. 외부 모델 연결 설정이 있는 기능은 키·서버·비용·연결 테스트가 갖춰진 경우에만 실제 AI 연동 기능으로 설명한다. 현재 Python 서버에는 AI 사진 변환 경로가 구현되어 있지 않으므로, 사진 편집이 모든 실행 방식에서 제공된다고 주장하지 않는다.

## 데이터 신뢰도 확보 계획

현재 출처 설명 파일에는 한국디자인진흥원과 KOTRA의 데이터명이 기재되어 있지만, 그 자체로 원본 레코드를 수집·정제·연결했다는 증거가 되지는 않는다. 제출 전에는 각 데이터의 공식 URL, 제공기관, 수집일, 원본 식별자, 이용조건, 사용한 필드와 연결된 화면을 추적할 수 있어야 한다.

후속 작업에서는 원본 스냅샷과 정제 규칙을 분리하고, 장소·기업·상품을 연결한 기준을 기록한다. 출처를 확인하지 못한 정보는 검증 완료로 표시하지 않는다. 대표 이미지가 AI 생성 이미지인 경우 실제 장소 사진과 구별하며, 행사 일정과 운영정보는 방문 전 공식 안내 확인을 제공한다.

## 사업화 가설과 검증

초기에는 여행객의 코스 탐색과 저장을 무료로 제공하면서 실제로 여행 계획을 단축하는지 확인한다. 이후 문화공간 또는 지역 브랜드가 다국어 소개 콘텐츠를 운영하도록 지원하는 서비스, 기관별 코스 제작·관리 등의 사업모델을 검토한다. 유료 제휴와 광고가 도입되면 추천 결과의 광고 여부와 편집 기준을 명확히 표시한다.

아직 매출, 제휴 계약, 이용자 조사, 구매 전환 성과는 확인되지 않았다. 따라서 시장 규모나 예상 매출을 확정값으로 제시하지 않는다. 운영비는 정적 호스팅, API 서버, 데이터 갱신, 외부 AI 호출로 구분해 실제 사용량과 견적에 따라 산정한다.

사용자 검증은 우선 5~10명의 소규모 사용성 평가를 제안한다. 이는 확보된 참여 인원이 아닌 계획이다. 참가자가 도움 없이 코스를 저장했는지, 추천 이유를 이해했는지, 방문에 필요한 정보가 부족하지 않았는지를 관찰한다. 클릭 수를 실제 방문이나 매출로 바꾸어 해석하지 않는다.

## 개발과 검증 계획

현재 개선 작업에서는 공개 파일 배포 준비, 오프라인 캐시 범위 제한, 코스 상세 주소의 오프라인 처리, 키보드 본문 이동, 선택 상태와 단계 진행률의 접근성 표시를 다룬다. API의 잘못된 JSON 입력은 서버 오류가 아닌 요청 오류로 반환하도록 수정한다.

다음 단계는 원본 데이터 근거 확보, 대표 코스 운영정보 확인, 주요 언어의 전체 여정 검수, 실제 모바일 기기에서의 사용성 확인이다. 계정·외부 AI·실시간 정보처럼 서버에 의존하는 기능은 별도 배포 및 검증을 마친 뒤 기능표에 반영한다.

공모전 제출물은 이 서비스 설명을 바탕으로 실제 모집요강의 항목과 분량에 맞춰 편집해야 한다. 신청자 정보, 서명, 참가자격, 기존 출품 이력과 공식 양식은 확정된 자료로 작성하며 임의로 채우지 않는다.
