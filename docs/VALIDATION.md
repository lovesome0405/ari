검토 기준 커밋: fc6d2f520ec33cc9bfdf10e7a9882003b9423a5f

## 수행한 검증

- JavaScript 구문 검사: app.js, admin.js, service-worker.js
- 서비스워커 회귀 테스트 8개: 코스 쿼리 주소, 루트 주소, API·인증·외부 범위 제외, 타 앱 캐시 보존, 캐시 갱신, HTTP 500 대응, 오프라인 503, 오프라인 안내 화면
- Python HTTP API 테스트 4개: 카탈로그와 없는 코스, 저장·조회·삭제, 객체가 아닌 JSON, 필수값 없는 저장
- 공개 파일 패키징과 HTML의 로컬 정적 파일 참조 확인

## 변경 내용

공개 앱 화면과 명시된 정적 데이터만 캐시한다. API 응답과 Authorization 요청은 가로채지 않는다. 코스 식별자를 포함한 주소도 동일한 공개 HTML을 활용하고, 데이터 선택은 기존 프론트 로직을 유지한다. 네트워크 지연은 4초 이후 캐시로 대체한다. 앱과 관계없는 캐시는 삭제하지 않는다.

본문 바로가기, 선택 버튼 상태, 현재 탐색 위치, 추천 단계 진행률과 모션 줄이기 설정을 지원한다. 잘못된 JSON 자료형은 HTTP 400으로 반환한다. scripts/build_static.py는 공개 웹 파일만 dist로 복사한다. scripts/demo.py는 동일한 폴더와 로컬 API를 실행한다.

## 남은 확인 사항

- 새 Notion 공고의 본문과 공식 제출 양식을 확보하지 못했다. 대회명·마감일·심사기준·필수 데이터·양식 일치를 확인하지 못했다. docs/PROPOSAL.md는 서비스 기획 원고이며 공모전 최종 제출본이 아니다.
- 기존 CONTEST_POSITIONING.md는 산업부 공모전을 대상으로 작성되어 있다. 새 공고와 동일한 대회라고 추정하지 않는다.
- 공공데이터 출처 설명에 기재된 기관·데이터명이 실제 원본 수집과 필드 단위 활용 증거를 대신하지 않는다.
- 실제 모바일 브라우저, 외부 지도, 외부 AI 호출, Spring Boot 서버와 MySQL, 계정 기능은 이번 테스트에 포함하지 않았다.
- Python 저장·반응 API는 로컬 시연용이다. 공개 다중 사용자 서비스에는 인증·사용자별 데이터 분리·운영 배포가 필요하다.
- 기존 GitHub Pages 배포는 워크플로를 통해 이루어진다. 이번 변경은 별도 브랜치에서 검토할 수 있으며 main 및 운영 화면의 반영 상태는 별도로 확인해야 한다.
